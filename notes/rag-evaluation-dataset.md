# RAG 评估：评估数据集

> 由真实问题、参考证据、参考答案和难例组成的可重复测试集。

## 题型分层
一份可用的测试集按六类题型分层采样：单文档简单查找、跨文档综合、版本冲突、无答案、越权访问、多轮追问。每类不少于 20 条，否则该类的分数波动会盖过真实差异。只堆简单查找题会让 Recall@5 虚高到 0.95 以上，而线上失败几乎都集中在后四类。

## 标注什么
每条样本至少标注：问题、参考证据的 chunk id 列表、参考答案要点、期望行为（作答 / 拒答 / 反问）。证据 id 是关键，缺了它只能评端到端对错，无法把失败定位到切分、检索还是生成。单条标注成本约 5–15 分钟，300 条规模的首版大致要两人周。

## 难例配比
无答案样本占比不低于 15%，用来量化拒答率；越权样本要附带调用者身份，验证权限过滤发生在检索阶段而不是靠生成阶段兜底。这两类按二值评分，答了就算失败，没有部分分。

## 冻结与扩充
测试集一旦冻结就不再改参考答案，否则不同版本之间的分数不可比。线上新捞到的失败样本先进增量集，每季度合并一次并重跑全量基线。
