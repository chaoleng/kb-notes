# 大语言模型（LLM）：LLM 上下文窗口

> 模型一次请求能够接收的输入和输出 token 总量，决定可放入多少检索资料。

## 预算是输入输出共用的
窗口标称 128k 指的是 prompt 加生成的总量，不是输入独占。若把证据塞到 126k，留给回答的空间只剩 2k，长答案会被中途截断成半句。工程上先按 max_tokens 预留输出，再拿剩余额度装输入。

## 长上下文的位置偏置
同一段证据放在开头或结尾时被正确引用的概率，明显高于放在中段，这就是常说的迷失在中间。实践中把重排后得分最高的片段放最前，次高的放最后，把弱相关的夹在中间，可以在片段数较多时挽回一部分准确率。

## 一份可用的预算分配
以 32k 窗口为例：系统指令与输出格式约束 1k 到 2k，检索证据 12k 到 16k，对话历史 4k 以内，输出预留 2k 到 4k，其余留作安全冗余。证据部分按 512 token 一块算，大约只能放 24 到 32 块，这直接决定重排后取几条。

## 超限时的截断优先级
先砍最旧的对话轮次，再砍重排分最低的片段，然后对长片段做句级压缩，最后才动系统指令。系统指令和输出格式一旦被截，模型会丢掉引用格式，后果比少几条证据严重得多。
