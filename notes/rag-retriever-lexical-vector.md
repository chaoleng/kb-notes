# 检索器（Retriever）：关键词检索与向量检索

> BM25 等关键词检索擅长精确术语，向量检索擅长语义相近表达。

## 两条通道的打分方式
BM25 沿用词频与逆文档频率的直觉：查询词在某段落里出现得越密集、在全库里越罕见，得分越高；参数 k1 控制词频饱和（常取 1.2–2.0），b 控制长度归一（常取 0.75）。向量通道把 query 和 chunk 各自编码成 768 或 1024 维稠密向量，用余弦相似度在 HNSW 上取近邻。两者的分值空间没有可比性，不能直接相加。

## 关键词通道的强项
产品型号 A7-3200、错误码 ERR_1042、版本号 v2.14、人名和函数名这类字符串，只要分词没把它们切碎，BM25 基本必中，且结果可解释——能指出是哪个词命中的。代价是完全不认同义词：用户问「登录一直转圈」而文档写「认证超时」，词面零交集，得分直接归零。

## 向量通道的强项与盲区
向量不依赖同词即可匹配同义表达，对口语化长句和改写提问明显更稳。但它对精确编号、专有名词、版本号和否定词不敏感，「不支持 SSO」与「支持 SSO」的余弦相似度常在 0.95 以上；向量相似并不等于事实相关，语义邻近的干扰段落会稳定挤进前十位。

## 选型的判断依据
先统计线上 query 构成：含数字或标识符的问题若超过三成，只留向量通道往往让 Recall@10 掉十个点以上。两类能力互补而非替代，实际系统一般同时保留，交给[混合检索](note://rag-retriever-hybrid)做融合。
