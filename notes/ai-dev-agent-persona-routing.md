# Agent 人格分工与模型路由

> 每个 LLM 节点绑定一个专家人格决定生成方向，达标与否交给对应的确定性校验工具。

## 四种人格

| 人格 | 负责阶段 | 关注点 | 对应校验 |
|---|---|---|---|
| 高级产品经理 | Index / 需求 | 边界、验收标准、非功能需求、“不做什么” | Index 章节完整性 |
| 高级开发技术专家 | 架构 / 选型 / Infra / Backend | OWASP、越权与注入、N+1 与缓存限流等性能项 | Semgrep、Bandit、性能基准 |
| 前端 UI 设计专家 | Frontend | 视觉层级、WCAG 无障碍、响应式 | axe-core、视觉回归 |
| QA 专家 | Unit / E2E | 用例完整性、边界覆盖 | 覆盖率统计、Playwright 报告 |

## 生成方向与达标判定分离

人格的作用范围仅限于“往哪个方向写”，它不决定“写得够不够好”。后半句由 [Skill 层](note://ai-dev-skill-quality-gate) 用工具跑出来的结果回答，模型对自己产出的评价不进入判定链路。这样换模型、换 prompt 都不会动摇验收标准，回归时也能把生成质量的变化和判定口径的变化区分开。

## 按任务类型路由模型

路由策略借鉴 Agyn 论文的做法，不用一个模型贯穿全程：需求分析、架构设计这类推理型任务走综合能力更强的模型；Backend、Infra 这类实现型任务走代码专用模型；质量门打回后的修复建议，走对应角色本身的模型而不是统一挂在最强模型上。

## 为什么值得拆

单模型贯穿的做法在成本和质量上同时吃亏：推理型任务用小模型会漏掉非功能需求，实现型任务用通用大模型则为同样的代码补全付更高单价。按阶段路由后，模型选择变成配置项，可以针对单个阶段做 A/B 对比，而阶段契约、质量门口径都不用跟着改。
