# omp Harness：专用工具优先的工具策略

> 读写、检索、结构遍历、跨文件重命名都有专用原语，因其输出可寻址且编辑带乐观锁而优先于 shell 等价物。

## 每类操作都有对口原语

文件与目录读取走 `read`，创建或覆盖走 `write`，局部修改走 `edit`，正则查找走 `grep`，路径匹配与结构遍历走 `glob`，按语法形状搜索与批量改写走 AST 原语，跨文件重命名走语言服务器。`cat`、`ls`、`find`、`sed`、`rg` 都有对口替代。

## 优先的三条理由

第一，专用工具的输出受控：超长结果会被截断并留下可寻址 id，按需分页取回，不会一次性灌满窗口；shell 的 stdout 一旦堆积就既难截取又难复用。第二，编辑带快照指纹的乐观锁，基于过期内容的修改会被拒绝，正则替换没有这层保护，改错了照样落盘。第三，语言服务器重命名按符号解析，覆盖全部引用点，文本替换则会漏掉别名导入、误伤同名字符串。

## shell 的合理边界

shell 留给真正的外部二进制和短管道统计：跑构建、调一次 `git`、用 `wc -l` 数行、`sort | uniq -c` 算频次、`diff` 比对、算校验和。判据是这次调用产出的是一个事实或副作用，而不是在搬运本可以用专用工具直接取到的字节。

## 违背策略的代价

用 shell 代劳读写的典型后果是：全量 `cat` 把长文件铺进上下文、盲目 `sed -i` 覆盖并发改动、`find` 遍历把产物目录一并扫进来。这些失误都不会立刻报错，而是在几轮之后以改错位置或窗口耗尽的形式出现。具体的读写闭环见 [文件读写](note://omp-harness-file-io)。
