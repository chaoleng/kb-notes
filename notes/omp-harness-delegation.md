# omp Harness：子 Agent 委派与并行编排

> 用 task 派生背景子 Agent 时，指令必须自包含、批量派发才有真并行、文件所有权与接口契约必须提前拆清。

## 自包含指令

`task` 派生的是背景子 Agent，它拿不到父会话的任何历史：没读过的文件、上一轮敲定的取舍、用户原话里的口径，它全都不知道。所以任务书要写全三段：改哪些文件与符号、具体做什么改动、什么算完成的可观察标准。共享背景写进批次 `context`，长素材换成 `local://` 引用。

## 批量派发才是并行

并行来自一次 `tasks[]` 里放多个条目；先派一个、等它回来再派下一个，只是给串行换了个外壳。只读调研派给更快的 scout，改代码派给有编辑能力的类型，同一个 Agent 一趟完成调查加修改可少一次往返。

## 并发前先拆所有权

同一个文件被两个子 Agent 同时改，结果不保证能合并。所以派发前主 Agent 自己要先做分解：把接口、数据结构、字段命名这类跨任务契约定死写进 `context`，再按文件所有权切片，不可避免的共享边界指定单一负责人串行处理。

## 校验留给最后一次

并发期间的子 Agent 一律不跑格式化、lint 和全库测试：兄弟任务的改动还落地到一半，这时候跑出来的失败大多是幻影。全量校验由主 Agent 在所有任务收敛后统一跑一次。子 Agent 报告完成也只代表进程正常退出，产物是否可用需要主 Agent 复验。
