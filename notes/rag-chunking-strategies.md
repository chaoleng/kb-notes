# 文档切分（Chunking）：切分策略

> 固定长度、递归切分、按标题切分、语义切分和父子文档是常见策略。

## 五种切法的实现差异
固定长度按 token 硬切，实现最简单，常见设置是 256–512 token。递归字符切分依次尝试 `\n\n`、`\n`、`。`、空格这几级分隔符，只有仍然超限时才退化为硬切。Markdown 标题切分沿 H2/H3 边界划分，并把标题路径写进 metadata 供过滤使用。语义切分逐句编码，相邻句余弦相似度跌破阈值（经验值 0.75 上下）处断开，编码开销大致是规则切分的十倍。

## 尺寸怎么配文档类型
FAQ、工单这类短答案文本用 128–256 token 就够；产品手册、接口文档用 512 token 并附标题路径；法规、论文这类长论证用 1024 token，或者交给父子结构承载。中文估算按 1 个汉字约 1.5 token，512 token 差不多是 340 字。

## 明显会失效的输入
长表格硬切后表头与数据行分离，召回片段无法解释列含义，应整表成片或给每行补一份表头。源码按行切会断开函数体，宜以函数或类为单位。扫描件 OCR 之后段落顺序错乱，双栏 PDF 要先做版面还原再进切分。

## 选型顺序
先用递归字符切分跑通基线并测出 Recall@10，再按文档类型换成标题切分或[父子片段检索](note://rag-chunking-parent-child)；只有当语义边界确实模糊、标题层级又不可靠时，才值得付出语义切分的成本。
