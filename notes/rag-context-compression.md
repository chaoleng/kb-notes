# Prompt：上下文压缩与证据精简

> 在不丢关键事实的前提下缩短证据长度，用抽取、摘要或按查询删句控制输入规模。

## 三条压缩路线
句子级抽取按与查询的相关度给每句打分，保留 Top-N 句并维持原顺序，一个字都不改；LLMLingua 更激进，直接在 token 粒度丢弃低信息量的词。生成式摘要让小模型把多段证据改写成要点，压缩比可到 5:1，代价是二次改写。按相关度删句只清掉免责声明、页脚和过渡句，压缩比约 1.5:1，最保守。

## 压缩比、延迟与成本的三角
压缩比每上一档，数字、版本号、否定词被删掉的概率就上升一档；抽取式至少不会把「不支持」写成「支持」。压缩自身多一次模型调用，小模型过一遍 4k 证据约增加 200–600ms 和一笔 token 开销。上线前量两个数：实际压缩比，和压缩前后正确率的差值，掉过 2 个百分点就回退。

## 压缩后引用会失真
摘要句在原文里找不到逐字对应，引用粒度会退化到文档级。压缩时要把每个保留单元的原片段 id 与句子偏移一并带出；摘要模式下让小模型给每条要点标注所依据的片段 id，生成端只引用这些 id。排布顺序仍按 [上下文组装](note://rag-prompt-context-assembly) 走。

## 什么时候不值得压
证据占窗口不到 40%，或单片段已短于 200 token 时就别压，只多一次失真机会。合规、医疗、财务口径的高风险问答应关掉生成式压缩。真正该压的是多轮累积的对话历史，和二十段以上证据的深度调研。
