# Prompt：上下文组装

> 按照相关性、来源可信度、时间和互补性排列片段，并控制总 token 预算。

## 排序：最能直接回答的放最前
按重排分数降序排列，能直接回答问题的证据放在证据区开头；分数接近时用来源可信度和更新时间打破平局，官方文档优先于社区帖子，新版本优先于历史归档。长窗口模型同样存在中间位置衰减，关键片段不要塞在中段。

## 去重与互补裁剪
同一事实常被多个片段重复表述，用 MinHash 或片段向量余弦大于 0.95 判重，同一事实只保留得分最高的那个来源，避免它占满整个窗口。空间不足时按互补性裁剪：优先保留覆盖不同子问题、不同实体的片段，而不是把同主题的前十条全塞进去。

## token 预算分配
先给回答留额度，例如 8k 窗口预留 1k 给输出，规则与格式说明约占 300–500 token，其余分给证据区，通常 6–10 段、每段 300–500 token。超预算时按整段从尾部丢弃，禁止把一段从句子中间切断。

## 保留定位字段
每段都带标题、来源 URL 或文档路径、更新时间和 chunk 序号。这些字段既让模型有东西可引用，也让人工排查冲突时能一眼回到原文，判断是资料本身矛盾还是拼接顺序误导了模型。
