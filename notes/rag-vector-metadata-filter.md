# 向量数据库：元数据过滤与权限

> 在向量相似搜索前后按租户、用户权限、版本、时间和文档类型过滤候选。

## pre-filter 与 post-filter
post-filter 先取 ANN 的 topK 再筛条件，实现简单，但当命中率只有百分之一时，取 100 条可能只剩 1 条可用，出现召回塌陷；补救办法是放大倍率取 topK×20，延迟随之抬高。pre-filter 把条件下推进图或倒排遍历，结果数量稳定，但过滤位图过稀时 HNSW 的邻居大量被跳过，图连通性被破坏，需要在选择率低于千分之一时自动回落到该分区的暴力扫描。

## 权限必须落在检索层
租户 ID、ACL 列表这类字段要作为强制条件拼进过滤表达式，由服务端注入而非调用方传参。指望在 Prompt 里写「忽略你无权查看的内容」是无效的：越权片段一旦进入上下文就已构成泄露，模型是否引用并不改变事实。

## 权限字段的同步
文档搬移目录、成员退出群组时，权限只改在业务库而没回写到向量库，就会留下一段可被检索到的窗口。做法是把 acl_version 与文档一起写入元数据，检索时比对权限服务的当前版本，过期则跳过该片段，并用增量任务在分钟级刷新受影响的分片。

## 过滤过窄时的降级
条件叠满后候选为空，应按预设顺序放宽：先时间范围，再文档类型，最后才调大 topK，权限与租户条件永不参与放宽。把「过滤后候选数」打成指标，空结果率骤升通常意味着某个元数据字段在写入侧换了取值。
