# Embedding：向量版本与语义漂移

> Embedding 模型升级会改变向量空间，旧向量与新查询向量可能不再兼容。

## 为什么必须全量重算
换模型等于换了一套坐标系，新旧向量之间算出来的距离没有意义。两代向量混存会制造一类很隐蔽的故障：新版向量因分布差异整体得分更高，旧版片段几乎再也进不了 Top-K，线上指标只是小幅下滑，实际上半个库已经失联。升小版本、改归一化方式或改动前缀模板，都要按换模型对待。

## 双写与灰度
新建 `index_v2` 独立索引，离线把全量片段重编码一遍，这期间新增文档同时写 v1 和 v2。重算完成后用流量开关按 1% → 10% → 50% 推进。查询侧的编码器要与所查索引版本绑定，只切索引不切编码器，等于拿新问题去问旧空间。

## 索引要带的字段
每条记录写上 `embedding_model`、`model_version`、`dim` 和编码时间戳，入库时校验维度与版本是否匹配。查询前做一次版本前置检查，不一致就直接拒绝并报错——比悄悄返回一堆乱序结果容易排查得多。

## 回滚判据
切换前后跑同一份回归问题集，对比 Recall@10 和人工判定的答案正确率，任一项掉超过 3 个百分点就切回 v1。v1 索引保留到 v2 稳定运行两周之后再删，否则回滚只剩重跑全量这一条路。
