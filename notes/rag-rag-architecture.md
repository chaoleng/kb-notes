# RAG（检索增强生成）：RAG 系统架构

> 从数据源、索引、检索、上下文编排到模型生成，RAG 是多个组件协作的系统。

## 离线加工链路
数据源（wiki、对象存储、业务库、工单系统）先由解析器抽出纯文本与结构，清洗后按 400–800 token 切分并保留 10%–20% 重叠，再批量调 embedding 写入索引。这条链路按增量或定时触发，关注吞吐和幂等，而不是单次延迟。

## 在线问答链路
查询改写与意图分类之后进入召回、重排、上下文编排、生成、引用与留痕。它是一条请求内串行的流水线，任何一环变慢都直接体现在 p95 上，因此重排和生成通常各自设独立超时。

## 索引层的三种结构
向量索引（HNSW 或 IVF-PQ）负责语义近邻，倒排索引（BM25）负责型号、编号、专有名词的字面命中，元数据存储承载租户、权限、时间、文档类型等过滤条件。三者共用同一套 chunk id，缺任何一个都会让某类查询整体塌陷。

## 每层的典型失败点
解析层丢表格或把页眉页脚串进正文，切分层切断语义单元，embedding 层换版未全量重建导致新旧向量空间不一致，检索层过滤条件写错造成零召回，编排层超窗被静默截断。每层单独埋点，只盯端到端准确率定位不到责任方。
